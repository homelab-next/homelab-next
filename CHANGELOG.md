# Changelog

All notable changes are recorded here, following [Keep a Changelog](https://keepachangelog.com/en/1.1.0/)
and [Semantic Versioning](https://semver.org/). The release workflow refuses a tag whose version
has no section below.

## [Unreleased]

### Fixed
- Guests: the `registry-hosts` render target no longer writes `role: <guest capability>` for each host, so merging the fragment into a registry cannot turn a guest's capability claim (say `cap:agent-runtime`) into the host role the agent runner is found by. **Breaking for overlay sites:** a registry built by merging the fragment sets each host's `role` itself.
- Review tier: a change to `homelabnext/compute/loader.py`, `homelabnext/compute/gen/registry_hosts.py` or `homelabnext/invariants/plugins/pillar_x.py` (what ADR-0039 steps 6 and 8 judge a registry with) is human-approve.
- Swap: `apply_switch` refuses a standing promotion dated after the real local date (`HNX_TODAY` or `today=` set ahead would post-date its rollback window), and the new `apply_promotion(text, plan, today=)` runs the same date, field and recompute checks for a promotion with no module swap (an old-lab switch); [docs/swap.md](docs/swap.md) covers the one-half case and that merge lag shortens the window.
- Lab-in-a-box: the bind guard judges the controller by its name, image, entrypoint or API port, and refuses a volume, bind or tmpfs over its `/run/secrets`.
- LLM gateway and `hnx registry bindings --gateway`: a spec's `roles:` path is refused when absolute, when it leaves the root the caller gives (`--root`; by default the working directory when the spec is in it, else the spec's directory; `..` inside it is fine), or when a symbolic link is on its path (each component opened without following one); both read it through one validator, `RoleTable.loads`.
- LLM gateway: the spec's role table is read without following a symbolic link on its path, as `hnx registry bindings` reads its inputs.
- **Breaking for overlay sites:** `hnx site validate` refuses a resolver `authoritative_for` a zone under the registry's alias zone, as it refuses a static record there (the alias zone itself, which the DNS zone generator renders with its own SOA and NS, may be served) ([ADR-0039](docs/adr/0039-one-primary-per-capability.md) decision 2).
- **Breaking for overlay sites:** LLM gateway: a self-declared backend host that is a capability's primary alias is that registry service and meets its checks (lab zone, port, scheme); it skipped the zone check, so a backend in a non-lab zone rendered as local. A primary that serves a second API port cannot be reached through its alias on that port: register the second port as a row of its own ([ADR-0039](docs/adr/0039-one-primary-per-capability.md) decision 3).
- Lab-in-a-box: the bind guard measures the job API token the orchestrator service itself mounts at `/run/secrets/orchestrator-token`, so another service's long secret cannot stand in for a weak one.
- Checklist X-12 ([ADR-0039](docs/adr/0039-one-primary-per-capability.md) decision 8) follows no symbolic link: a symlinked `services.yml`, or one in a symlinked directory, pointed it at a file outside the repository, and an unreadable registry's error quoted its lines into the evidence. Such a path is now named and never read, and an error reports the path and error type only. It selects registries by content (a top-level `registry_version` key, read from the parsed document, so a quoted, explicit-key, JSON or merge-key (`<<:`) registry counts; a `services.yml` that is not one YAML document is named, not skipped) at any depth, lists the directory classes it does not search, judges every registry instead of stopping at the first invalid one, and states the date it judged, marked when `HNX_TODAY` set it.
- Promotion ([ADR-0039](docs/adr/0039-one-primary-per-capability.md) step 7, review follow-ups): `plan_promote` bounds `rollback_days` to 1..90 and `apply_switch` refuses a promotion not dated the day it is applied (`today`, default `HNX_TODAY`), so a caller can no longer pick the window's start or stretch it until ADR-0043's ledger binds both; `apply_switch` refuses `legacy` for an incumbent whose outgoing provider is a module this repository deploys, and holds a `legacy` incumbent to the outgoing product. [docs/swap.md](docs/swap.md).
- `hnx guests validate` with a registry ([ADR-0039](docs/adr/0039-one-primary-per-capability.md) step 6, review follow-ups): addresses are compared as addresses (an IPv6 registry address written uncompressed escaped the renamed-guest check); `cap:agent-runtime` is accepted only on a registry host whose `role` is `agent-runtime` (a row-less guest took it anywhere, so a runner `hnx agent access` cannot find passed); a row-less guest may declare its registry host's own `role`, and a `planned` guest holds no row yet as a `retired` one does; the group of a capability no row serves is taken only by a guest declaring that capability. docs/compute-model.md, "Guests against the registry".
- LLM gateway: a spec backend that reaches an `eval`, `retiring` or `legacy` registry row is refused, whether it is named after the row, names its record (or a name under it) as a self-declared host, or uses a capability's primary alias with another port than the primary's ([ADR-0039](docs/adr/0039-one-primary-per-capability.md) decision 3).
- **Breaking for overlay sites:** `hnx site validate` refuses a static DNS record in the registry's alias zone (`<svc_label>.<domain>`): only the registry's own records live there, so a made-up alias cannot be pointed at a candidate row ([ADR-0039](docs/adr/0039-one-primary-per-capability.md) decision 2).
- Orchestrator exec runner and controller: sessions inherit no unlisted variable and never the event token; no subreaper; a stop ends admission before the drain (`KillMode=mixed`); signals caught first (PR 2.7b review).
- Orchestrator queue: admission compares tasks by a stored digest and reads no task text; a backend-down requeue uncounts its attempt in the same write; the submit window's count is index-bounded by time (PR 2.7a).
- Gateway: the reply scanner reads a top-level key holding invalid UTF-8 as `json.Unmarshal` does (found by `FuzzJSONScan`).
- Orchestrator: `pathscope.CheckWrite`/`CheckRead` refuse a path with a hidden segment (found by `FuzzCheck`) or a backslash, NUL or control character.
- The Go LLM gateway's config reader refuses everything the contract's schema refuses: a `null` where the schema allows none (it read as false, an empty string or no list), a count limit of 0 and a cost limit of 0, a `backend` or `model` outside the schema's pattern, a `base_url` host with upper case, an underscore, an IPv6 literal, a trailing dot, an empty or six-digit port, a `profile:` owner that is not a slug, and every length over the schema's maximum. Its tests now parse the schema's examples and negatives in place and the shared `conformance/fixtures/gateway_config_vectors.json`, which names each intentional difference ([docs/gateway.md](docs/gateway.md)).
- Tests: `tests/golden` and `tests/status` collect in one run in either order. `tests/golden/test_golden_runner.py` imported its constants with `from conftest import ...`, and with no `__init__.py` every `conftest.py` is the module `conftest`, so `pytest tests/golden tests/status` handed it the status hub's conftest and collection failed. The constants moved to `tests/golden/golden_helpers.py`; a gate test refuses any test module importing `conftest` by name.
- `homelabnext.__version__` on a checkout that is not installed is `homelabnext._version.VERSION` (the version packaging stamps and the changelog gate reads), not `0.0.0+local`, which no changelog section names: `tests/events/test_deploy.py` failed on an uninstalled tree.
- Orchestrator prompt: two state keys that fold to one line are both kept (a key already one line keeps its name, the other is marked ` [collision N]`) instead of one overwriting the other at random (docs/orchestration-controller.md, "A job's prompt").
- Docs drift: docs/architecture.md and docs/build-order.md name the own gateway in `orchestrator/` (ADR-0038, ADR-0026) as LiteLLM's replacement at the gateway cutover; the controller stand-in, its adapter, recorded target and docs/orchestration-controller.md say the `reject-unknown-agent-key` and `max-attempts` fixes landed privately on 2026-10-22 (they were still called proposals) and that ADR-0026 does not port the opt-in; cites of the private `internal/hermesagent` package say they hold only at `a52a1c4`, and the status hub's queue-summary and the adapter's state map cite `orchestrator/internal/store`; `examples/modules/core-modules/module.yml` no longer says the loader does not exist; docs/README.md lists the `docs/modules/` reference pages.
- The `vllm_server` health hook asks each instance what it serves with `follow_redirects: none` and `use_proxy: false`: the `ansible.builtin.uri` task sends the API key (`Authorization: Bearer`), and the module defaults followed a GET's redirect to any origin with the header and handed the request to `HTTP(S)_PROXY`. A `3xx` now fails health. A role test scans the roles' tasks and handlers and the playbooks for `uri` and `get_url` tasks (any form, `action:`/`local_action:` included) that carry a credential (a credential header, a URL password, basic auth, a client key or certificate, userinfo in the URL): a `uri` task needs `follow_redirects: none`, `use_proxy: false` and no 3xx success code; a `get_url` task (it has no `follow_redirects`) needs `use_proxy: false` and every credential header in `unredirected_headers`. A templated `headers` value is refused unless reviewed, and `module_defaults` may not set credential arguments for either module.
- The `needrestart` and `lynis` alert scripts (`needrestart-check`, `lynis-dpkg-verify`) post with their own opener: no redirect followed and no proxy from the environment. They sent `Authorization: Bearer <token>` through urllib's stock `urlopen`, which resent a POST answered `301`/`302`/`303` as a GET to any `Location`, the token included, and handed the request to `HTTP(S)_PROXY`. The roles already refuse a token over plain http, so the proxy path is defence in depth. A `3xx` now fails the send, so the alert stays owed (exit 2) until the notify URL is fixed. Both scripts also refuse an empty token (it was sent as a bare `Authorization: Bearer `) and a token that is not printable ASCII (a newline or control character, a pasted typographic quote) before building the header, with a message naming the token file and never the token, and the alert stays owed: `http.client` refused such a header with an error that quoted the whole value, token included, into the job's stderr. The scripts run on lab hosts and cannot import homelabnext, so each carries the opener and the check inline.
- Registry: the model client sends its key over plain `http` only to a loopback host unless the caller opts in (`homelabnext._http.check_plaintext`, the rule every other credentialed client follows): `authorized`, `ModelClient`, `probe`, `probe_all` and `check_serving` take `allow_plaintext` (default false), and `hnx golden run`/`pins report`/`canary` take `--allow-plaintext` beside `--key-env`. Without it the send is refused with `ModelError("misconfigured")` (a probe reports `error`) and nothing is sent. **Breaking for overlay sites:** a keyed call to a non-loopback `http` backend or gateway (the K-14 probe, `hnx golden` with `--key-env`) now needs `allow_plaintext=True` / `--allow-plaintext`, or https.
- HTTP: the shared same-origin redirect handler refuses a redirect whose authority holds userinfo (`@`), a backslash or a percent-escape, and turns a bad port or bracket in the target into the `HTTPError` its callers handle. A same-host `Location` with userinfo passed the origin check (urlsplit drops it) and was followed into a URL `http.client` reads as another host, and a bad port raised `ValueError` out of the handler.
- Registry: `homelabnext.registry.models.authorized` refuses an API key holding anything but printable ASCII (a control character, or a character such as a pasted typographic quote, which `http.client` refused with an uncaught `UnicodeEncodeError`) with `ModelError("misconfigured")`, which does not quote it; nothing is sent. Such a key reached `http.client`, whose `ValueError` quoted the whole header value, key included, and escaped `ModelError`, so a probe crashed instead of reporting `error`.
- HTTP: `homelabnext._http.safe_opener`/`safe_urlopen` use no proxy (an empty `ProxyHandler`). `build_opener`'s default read `HTTP(S)_PROXY` from the environment, so a proxy there received the requests of every caller with their credential header, in clear for http: the gateway key writes (`hnx gen gateway`, the master key), the OpenAI-compatible, OpenBao (`X-Vault-Token`), ntfy and LLM-orchestrator conformance adapters, the status hub's HTTP collectors, the OpenProject client, and the Trino and REST catalog clients when no opener is passed. Every caller reaches a lab endpoint; a deployment that needs an egress proxy configures it explicitly, not through `HTTP(S)_PROXY`.
- HTTP: `homelabnext._http.no_redirect_urlopen`, the default opener of the events `HttpForwarder` and `NtfySender`, uses no proxy (an empty `ProxyHandler`, as `credential_opener` already did). `build_opener`'s default `ProxyHandler` read `HTTP(S)_PROXY` from the environment, so a proxy there received the request and its `Authorization` header, in clear for http.
- Registry: the model client's transport (`homelabnext.registry.models.urllib_transport`, behind `ModelClient`, `probe` and the golden runner) sends through `homelabnext._http.credential_opener`: no redirect followed and no proxy from the environment. It used urllib's stock redirect handler while carrying `Authorization: Bearer <api_key>`, so a redirect to another origin received the key, https was followed down to http, and a POST answered `301`/`302`/`303` was resent as a GET with no body. A `3xx` is now `ModelError("http")` whatever its body (an HTML page with a `302` used to be `malformed`), so a chat call raises it and a probe reports `error`.
- Events: `HttpForwarder` treats any `3xx` (none is followed) as a configuration fault (`MisconfiguredError`, the event stays pending until the URL is fixed) instead of a permanent refusal that marked the event `rejected`; the forwarder contract in docs/events.md says so.
- Health and restart correctness (review 2, F19, F20, F36). `compose_app` health fails on an empty `docker compose ps` (it used to loop over nothing and pass) and when a service of `compose_app_spec` has no container, and reads both the one-object-per-line and the single-array output formats. `vllm_server` restarts an instance whose API key file was rewritten (the engines read `EnvironmentFile` only at start, so a rotated key left them on the old one and the gateway got 401s), and retiring an instance removes its API key file and cache directory. `wazuh_agent` health reads the agent's `ossec.conf` (at `<home>/etc/ossec.conf`, the home being three levels above `wazuh_agent_state_file`) and fails when no `<address>` in it is the registry's manager (the manager is handed to the package at the first install only; addresses inside XML comments do not count). `compose_app` health accepts only `Health: healthy`, so a container without a healthcheck (drifted from the spec) fails. Retiring a `vllm_server` instance removes its key file and cache only when the instance name is a valid slug. Clearing `vllm_server_api_key_ref` leaves the old key files on disk (follow-up). **Breaking for overlay sites:** `compose_app` health now requires `compose_app_spec`; `wazuh_agent` health now requires `wazuh_agent_manager_id`, so an agent enrolled with a manager other than the registry's fails health until it is reinstalled or the registry is corrected.
- Events and notify: `HttpForwarder` and `NtfySender` follow no redirect. Through the shared same-origin redirect handler, urllib resent a POST answered `301`/`302`/`303` as a GET with no body, and a `2xx` to that GET read as an acknowledgement: the outbox marked an event `sent` (and notify reported a message delivered) that the server never received. A `3xx` is now `MisconfiguredError` for the forwarder (the event stays pending until the URL is fixed) and a `SendError` for notify. The new `homelabnext._http.no_redirect_urlopen` is the opener both use.
- HTTP: the shared same-origin redirect handler behind `safe_urlopen`/`safe_opener` follows a redirect only for a GET or HEAD; any other method's `3xx` is the `HTTPError` each caller already handles. urllib resent a POST answered `301`/`302`/`303` as a GET with no body and the `2xx` to it read as the write's result, so the gateway key writes (`hnx gen gateway`), the Trino statement POST, the REST catalog's table create, the OpenProject client's creates and the OpenBao, orchestrator and OpenAI-compatible conformance adapters could take a write that never arrived for done. Reads still follow a same-origin redirect.
- The `lynis` health hook fails when the last audit exited non-zero (it read the exit status and ignored it), when `report.dat` is missing or older than the last run by more than `lynis_max_run_seconds` (new, default 3600; the scan now removes the previous report before auditing), and when `dpkg-verify.json` is missing or older than the last run (a failed sweep leaves the old result in place). The broker filing is named `<YYYY-MM-DD>-lynis-<host>.md`: the old `lynis-<host>.md` never matched the example findings lanes' `filename_pattern`, so the broker refused every filing and `|| true` hid it (the refusal is now printed to stderr). **Breaking for overlay sites:** a findings lane whose `filename_pattern` does not accept the date-prefixed name refuses the lynis filing; an audit that exits non-zero now fails health.
- The `clamav` role stats the guest's freshclam configuration instead of testing the controller (`is file`), so clearing `clamav_private_mirror` removes the `PrivateMirror` line on the guest, and a changed line restarts `clamav-freshclam` through a new handler (freshclam reads its configuration only at start). The scan script already records a clean exit when none of the configured paths exist (`ansible-a-l--practice--6`): that is the documented "nothing to scan" case, left as is.
- Approvals (review 2, F16; ADR-0034 decision 4, amended 2026-11-06): the person is named by one claim, the IdP's `preferred_username`, across the status hub, the auth-proxy contract and the SSH CA. The hub reads `X-Auth-Request-Preferred-Username` instead of `X-Auth-Request-User` (which carries the proxy's user-id claim, so every approve and deny through the documented setup was `403`), and the generated edge snippet and realm now carry the claim on every client. **Breaking for overlay sites:** an edge that does not use the generated `hnx_forward_auth` snippet must copy `X-Auth-Request-Preferred-Username` (a hub behind one that copies only `X-Auth-Request-User` sees no identity and answers `403`); `hnx ssh-ca` refuses an `oidc.user_claim` other than `preferred_username`; `agents.yml` `private.identity_header: X-Auth-Request-User` is still taken, with a warning, and not obeyed; `IdentityHeaders` takes a required `username` header; a non-default IdP must carry the username in `preferred_username`, and an overlay must not enable self-registration or an identity-brokering provider that lets a user choose their username. See [ADR-0034](docs/adr/0034-single-sign-on-oidc-idp-behind-a-neutral-contract.md) and [docs/status.md](docs/status.md).
- Status hub: `ingest` keeps the stored reading when a pushed observation is older than it (a late or replayed event used to replace a newer state); an equal or newer one still replaces it, and the source still counts as heard from. The OpenProject webhook receiver answers 500 when the feed fails on a delivery instead of dropping the connection.
- Docs: the OpenProject change feed and webhook receiver, and push-event status sources (`StatusHub.ingest_event`, `status.observed`), are marked stage 2, library only: no command, unit or publisher runs them yet. The wiring is tracked as developer follow-ups in `docs/projects.md` and `docs/status.md`.
- The `trivy` role's CycloneDX SBOM run takes the same options as the scan (`--severity`, `--skip-db-update`, `--db-repository`), so an offline guest or a mirror is honoured on that line too; the test asserts the full command line.
- **Breaking for overlay sites:** the `trivy` role pins `trivy_version` to `0.76.1` (tagged 2026-10-21, past the 14-day cooldown), installs exactly that package and always holds it; an empty `trivy_version` (the repository's newest, unheld) is now refused for every profile, and `tools/pin_freshness.py` tracks the pin.
- Novelty docs (`docs/novelty.md`) list `burst` among the statuses `corroborate` groups as signals, as the code does, and ADR-0036 decision 3 says a burst is a signal only for an entity quiet while learning: an entity noisy in both windows is reported once as `high_cardinality`, not as a signal (behaviour unchanged, now documented and pinned by a test). A doc test holds the documented signal set to `corroborate.SIGNALS`.
- `hnx invariants run --notify-cmd` is refused (usage error, exit 2) without `--notify-ceiling`; it used to page at a default `red` ceiling, an undeclared reader (ADR-0033 decision 6, clarification amended 2026-11-06). The stdout pager keeps `red`. **Breaking for overlay sites:** an invariants timer that passes `--notify-cmd` with no `--notify-ceiling` must add the flag (`red` keeps today's behaviour). Only the flag declares the ceiling: `run` takes no registry, so the registry notify row is not consulted. The check also fires without `--state`.
- Registry (`semantic_problems`): a public route needs auth. **Breaking for overlay sites:** a `services.yml` row with a `public_hostname` and no `auth` (the schema default `none`) or `auth: none` is refused with `a public route needs auth`, the message a module's rows already get (`modules/rules.py`); the edge used to publish it with no forward auth, so the app was open to anyone who reached the edge. `auth: mtls` on a public row is refused too: the edge terminates TLS and adds no client-certificate check, so it was never enforced. Module rows meet the same rule, overlapping zone CIDRs and IPv4-mapped IPv6 addresses are refused, and duplicate host addresses are compared as addresses. Before upgrading an overlay, run `hnx registry validate` on its `services.yml` and give each reported row `auth: idp` (with `roles`) or `auth: own`, or drop its `public_hostname`. See [ADR-0034](docs/adr/0034-single-sign-on-oidc-idp-behind-a-neutral-contract.md) (note on decision 3).

The loopback lab-in-a-box is unchanged; the engine's own set-up is an operator step in `TODO.md` §4. See [docs/modules/tlp.md (engine sign-in)](docs/modules/tlp.md#engine-sign-in).
- Reader-to-actor handoff (`homelabnext.agent.handoff`, ADR-0033 decisions 4 and 6): the reader's output keeps its TLP label, so a red reader's output no longer reaches a clear actor unlabelled; `broker/request` 1.1 adds an optional `tlp`, bound into the request digest. **Breaking for overlay sites:** `declaration_problems` refuses a handoff whose actor's receive ceiling (`readers.actor_ceiling`: the lower of what its `data_tier` lets it receive and its declared `tlp_ceiling`, `clear` when that is not a canonical label, so a `cloud-allowed` actor declaring `red`, `TLP:RED` or a non-label never reads as receiving `red`) is below what the reader may hold (`readers.held_label`: its receive ceiling, `red` when it states neither), and a reader or actor whose `tlp_ceiling` is not a canonical label agreeing with its `data_tier` (`readers.tlp_ceiling_problems`), so a `red`-ceiling reader can no longer hand off to a `clear` (`cloud-allowed`) actor; `accept` takes two new required keywords, `reader_profile=` and `actor_profile=` (ids must be the handoff's), labels the output with the strictest of the reader's held label, the pack's label (`pack_label`) and any TLP marker in the output, and refuses an output above the actor's ceiling and either profile's unsound `tlp_ceiling`. See [docs/modules/tlp.md](docs/modules/tlp.md) and [docs/modules/egress.md](docs/modules/egress.md) (the follow-ups).
- **Breaking for overlay sites:** a module manifest whose `lifecycle.remove.audit` names a plane that is neither a registered `hnx decommission` plane nor `contributions` is now refused by the loader (it loaded and silently audited less than declared).
- The module `licence` probe (warn at 30 days, page at 7, red on expiry) is marked "specified, not implemented" in `docs/modules.md`, the manifest schema and the follow-up list: nothing reads `licence.expires`.
- `hnx new schema` writes the layout X-03 checks (`examples/<name>.valid.json`, `negative/<name>.*.json`, a version-pinned `$id`), and its verify runs the X-03 check. `hnx new` names are matched in full (a trailing newline is refused), and `hnx new role` outside a checkout fails cleanly before writing files.
- The decommission `secret-names` plane no longer lists a sibling guest's secrets for deletion (key `app` matched `app_core_*`): a name that also belongs to another known guest (snapshot `guests`, or a `host_vars` file) is reported `AMBIGUOUS` for review.
  The most specific key wins: a target's own secrets (`app-core`'s `app_core_*` with a sibling guest `app`) stay firm remnants, `host_vars/<guest>/*.yml` names the guest, and a non-list snapshot `guests` is refused.
- The `contributions` audit plane is marked "specified, not implemented" in the manifest schema, the swap flow and the follow-up list; the loader still accepts the name.
- Agent context packs (`homelabnext.agent.pack`): input can no longer forge a stable section or slip past fence escaping, and pre-gate outputs are validated (schema, gate id, age) before a pack uses them, so a stale `ok` no longer gives a ready pack. **Breaking for overlay sites:** a `source: input` section declared `tier: stable` is refused by `assemble_pack`, `session_problems` (so `start_session`) and `manifest_problems` under the `readers` rule (so `hnx agent lint`); a stable section is neither nonce-fenced nor escaped, so input there could forge an `instructions [stable]` section. **Breaking for overlay sites:** a manifest or prompt-template delimiter that holds a line break, or reads as fewer than 4 visible characters, is refused (`pack.delimiter_problems`: by `assemble_pack`, `session_problems`, the `readers` lint rule and the prompt-template lint); `hnx agent lint` reports both refusals under `readers` and again under `sessions` for each profile the manifest names. See [docs/agent.md (context-pack assembler)](docs/agent.md#context-pack-assembler).
- `hnx guests`: `load_keys` refuses a `--keys` value that holds private key material or is not a single-line OpenSSH public key (the message never echoes the value); `render --target cloudinit --out` refuses ssh key names the keys file does not resolve instead of writing `<ssh-key:NAME>` into user-data, and `validate --keys` checks the names. The stdout render keeps the placeholder. A keys-file YAML error reports only its position (PyYAML quotes the source, which may be a pasted key), key names must match `[A-Za-z0-9_.-]{1,64}` and are unique, the comment after a key is printable ASCII, and the name check covers only the VMs cloud-init renders. Breaking for overlay sites: a keys file with non-public-key values, or a cloud-init guest naming an absent key, now fails.
- Tests: the real-tool checks may not skip silently in CI. A new `real-tools` job installs nftables and dnsmasq, allows unprivileged user namespaces, and runs the `nft -c` checks of the rendered firewall (`tests/network`, the `nftables_host` role refusal) and `dnsmasq --test`, then the root-only user-switching test (`setpriv`) as root, all with `HNX_REQUIRE_TOOLS=nft,dnsmasq,unshare,setpriv,ansible-playbook`, so a missing or unusable tool fails instead of skipping. ### Security
- **Breaking for overlay sites:** the private-overlay template's `HNX_REF` (the homelab-next commit `checks.yml` and `deploy.yml` check out into `hnx/` and the deploy runs with every deploy secret and root on every host) is the tracked file `locks/hnx-ref` (CODEOWNERS owns `locks/`), not an Actions variable, and both workflows refuse it unless it is one full SHA on homelab-next's `main` (`git merge-base --is-ancestor` against a freshly fetched `main`, with a full-history checkout, before anything from `hnx/` is installed or run). Before, any 40-hex value was accepted, so whoever could set the variable could point the deploy at an unmerged pull request's or a fork's commit, which GitHub serves under the parent's name. `checks.yml` gets an `hnx-pin` job the other jobs need and take the commit from. ADR-0021 (new decision 7), ADR-0028 and `docs/private-overlay.md` ("The pinned homelab-next commit") now agree on where `HNX_REF` lives and how it moves. An overlay adds `locks/hnx-ref`, takes up the new workflows and deletes its `HNX_REF` variable (`TODO.md`).
- The private-overlay template's `checks.yml` validates `lab/ssh-ca.yml` (`hnx ssh-ca check`) and `lab/secrets.yml` (`hnx secrets plan --spec`) on every pull request, each when present (new `lab-specs` job), so a broken spec shows before the operator applies it. The template's deploy SSH certificate role lives 1 h (was 30 m), at least the deploy job's 60-minute timeout, as its own comment requires; a test holds the two together.
- **Breaking for overlay sites:** the records decider (`homelabnext.records.decider`) no longer renames the inbox file into a decided lane, which kept the agent's inode (its owner and mode, and any hard link or open descriptor it held), so an agent could rewrite a note after it was approved and `complete()` acted on the rewrite. Every move now reads the note once through an `O_NOFOLLOW` descriptor, refuses anything but a regular single-link file (`LaneViolation`), claims it in `decided/.claims/` so a raced approve and deny have exactly one winner, and writes the validated bytes to a new file, all or nothing. `inbox/` and `decided/` must be on one mount: across mounts the claim is refused (`EXDEV`, "inbox/ and decided/ must be on one mount"); a crash mid-move leaves the lock in `decided/.claims/` and that name is refused until the operator removes it (the lock records the pid, host and UTC time of its move, the refusal says whether that pid still runs on this host, and `hnx records decide` lists what `decided/.claims/` holds when it refuses). `complete()` reads the decider's copy, and each `related:` entry must be exactly `decided/approved/<file>.md`. A decided note and its sidecar are mode 0640 less the decider's umask (`Decider(mode=)`), no longer readable by every local user: agents read `decided/` through the group of the decider's lane directories (setgid on them keeps it), so a site whose agents are not in that group loses read access. A site that put symlinks or hard-linked notes into `inbox/` or `decided/approved/` now has them refused. The register and strategy deciders read each intent through `Decider.read`, so a symlinked or hard-linked intent is `invalid` before anything is applied. The guarantee needs the decider to run as its own OS user, as before. See [ADR-0010](docs/adr/0010-records-lifecycle-as-an-api.md) and [docs/interfaces.md](docs/interfaces.md).
- New operator command `hnx records decide approve|deny|complete NAME --root DIR --by WHO [--reason TEXT]` (`homelabnext.records.decider.main`, routed by the new `homelabnext/records/cli.py`): the documented route for reviewing generic proposal notes when migrating a vault proposal queue (docs/broker.md) had no runnable mover. Exit 0 moved (each new path printed), 1 refused (any OS error included, such as running it as a user that may not write the lane), 2 usage (an empty `--by` included). `hnx records assign-uids|numbers|uid` are unchanged.
- **Breaking for overlay sites:** `model_store` no longer takes a fine-tune export by path, never follows a link in one, and refuses an export that holds anything but its listed files. A link planted beside an export made the root-run promotion chown or chmod its target; promotion now takes the export by descriptor (`model_store_files` `lock: true`), closes it to all but the store owner before listing it, refuses links, special files, unlisted or hard-linked files, and verifies each listed file by sha256 through its own descriptor (the vLLM unit's `ExecStartPre` check stays the last gate). An overlay whose promoted export holds files Studio wrote but no manifest entry lists (a README, a training log) must list them with their sha256 or remove them before the next run; a refused export's directories must then be removed or cleaned as root. See [docs/model-serving.md](docs/model-serving.md).

- CI's `trusted-gates` job no longer lets the pull request it checks set up the checker's interpreter: it calls `actions/setup-python` directly instead of the checkout's `python-deps` composite action, calls Python by the absolute path setup-python reports (a `$GITHUB_PATH` shim cannot stand in), and installs pip and the checker's dependencies from the base commit's `constraints/` and `pyproject.toml`. The swap-gate bootstrap fallback, which ran the change's own gate when the base's `modules/cli.py` lacked the string `"swap-gate"`, is gone: a base that cannot run a gate fails the job. `hnx modules review-tier` rates `.github/actions/python-deps/action.yml`, `constraints/bootstrap.txt`, `constraints/ci.txt`, `pyproject.toml` and the release transforms (`homelabnext/status/release_transforms.yml`, `release.py`; ADR-0033 decision 7) human-approve. CODEOWNERS, ADR-0030 and docs/agent.md now say plainly that code-owner review is advisory while `main`'s ruleset requires none, and docs/modules.md no longer states the trusted-gates guarantee as unconditional: the workflow file is still the change's.
- The release workflow signs only a commit the default branch already holds: right after a full-history checkout, before any action or script of the tagged tree, it fails unless the tagged commit is an ancestor of the default branch (whose ruleset admits only commits that passed the required CI checks). A `v*` tag on any other commit was built, attested and released before.
