- `tools/schema_check.py`: a schema marked `x-draft` (with the reason, naming its ADR) has no frozen baseline and `--freeze` skips it. Only a schema that was never frozen, or a new major, may be a draft: `x-draft` on a major with any frozen baseline is an error. Baselines are found by the `$id` name, not the file name, two files may not carry one `$id`, and a frozen name no live schema carries is an error. With `--base REF` (CI: the pull request's base) `schemas/_frozen/` is append-only: every file there at REF must still exist, byte-identical. So `x-draft` cannot lift the additivity gate off a released schema while its baselines are kept, and the append-only check is what keeps them; `--ci-base` picks the base in CI: an unreadable pull request base is an error, a push whose previous tip is zero or gone (a new branch, a force-push) is compared with `HEAD^`, and any other event or a shallow checkout with no base is an error; the step prints the base it used, and the register-ids and regression-tests steps follow the same rule. Without a base a deleted baseline is not detected; a symlink under `schemas/_frozen/` is always refused.
- MCP catalog (ADR-0024, `docs/mcp-catalog.md`, P-14): one reviewed record per MCP server, and every client config generated from it (`hnx mcp catalog check|list|classes|render|import`, `make mcp-check`). A record names its pinned origin with the package's reviewed `bins`, its program (an allowlisted `hnx` entry, or a first-party path rendered absolute under `checkout_root`) and the server's own arguments. Render generates the launch with fixed flags (`npx --prefix=<absolute npm_prefix>`, `uvx --no-config`), so the client's working directory cannot replace the pin, and settings, env and parameter keys may not configure the launcher; a third party's hosted server is an https `remote` URL. Check refuses literal secrets, unpinned launches and unreviewed records, and no message prints a value. A hosted server is an https URL naming a public DNS host (never an IPv4 address in any notation) and is `cloud-allowed`; a local-only profile is granted an internet-reaching server only by a named `internet_mcp` exception in the ceiling policy; no record sets a variable that loads code or redirects trust in the launcher (OpenSSL and TLS, proxies, glibc, shell and interpreter options); render refuses an `npm_prefix` that is the root, a symlink or not empty, and a symlinked `checkout_root`. Render runs the whole record check, needs the review policy, and accepts only profiles `hnx agent verify` accepts against a ceiling policy, which attests each profile's data tier and model role. Import drafts records from existing client configs and fails closed on credentials. The grant compiler, verify and lint judge grants against the catalog.

A03 runs a request StackStorm submitted, once, after a human approves it (agent approvals now say `tier_used: agent`); redelivered events are dropped by id and the runtime's datastore keys are HMAC-keyed. A01 and A02 speak the controller's job contract (source, failure classes, one resubmit, idempotency per failed run) and the submit handler sends the controller's jobs token. The lab-in-a-box bus requires a user per client, only the broker may publish decisions and proposals, and the nightly checks both. The NATS password goes only over TLS or to loopback.
