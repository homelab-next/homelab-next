- Module `modules/lake-writer/` ([README](modules/lake-writer/README.md), ADR-0049 decision 3): the log pipeline's lake writer as a feature module. One timer per table (a template unit, an instance is a table) runs `hnx-lake-writer commit`, which lists the labelled OCSF batches the pipeline stages in the object store (`<prefix><table>/<name>`), turns each line into a row with `homelabnext.lake.rows.row_from_event` (the row's `tlp` is `labels.hnx_tlp`; an event without a canonical label is refused, dead-lettered under `_rejected/` with its reason, and never given one), and commits each object through `Ingestor` (`write_batch` under the object key, then the checkpoint, then the delete), so a crash at any point replays with no row added. Ten tables, all FRESH in the new lake namespace `soc` (nine OCSF classes, four of them pinned by the module, and a raw archive the source census reads), each a `platform/lake_table` record. A namespace guard refuses any namespace but `soc` (the imported and migrated ones are named in the refusal) at configuration, writer, client and `open_lake`, and the role derives the namespace rather than taking it; a per-table lock and source keep one writer per table; a lake that is away is retried a bounded number of times and a run in which every row was refused fails. Hooks: readiness, main (creates the namespace and tables, never alters one), health (timers, `schema-check`, `status`), export, backup, restore, upgrade; install, upgrade and remove playbooks. No registry row (it listens on nothing). Needs the runtime release (role `hnx_runtime`) on the guest. No allowlist count rises.

Two `compose_app` containers: the aggregator (syslog 514/udp and 6514/tcp+TLS, the sensors' protocol on 6000, the manager's alert and archive files tailed with checkpoints; raw syslog forwarded unchanged to the manager's syslog input) and an enrichment sidecar that sets `labels.hnx_runtime` and `labels.hnx_tlp` with the core library's own rules (`homelabnext/tlp.py` and `homelabnext/logpipeline/` copied verbatim to the guest; a test proves the copy list is the complete standard-library import closure and a deployed layout labels a corpus exactly as the core does), from the observed source only (the peer, the address the manager recorded for an agent, or the client a trusted router recorded), never the event. - Module `modules/prometheus/`: opt-in HTTP(S) up/down probes (`prometheus_probes_enabled`, default false), the function an uptime monitor serves. A blackbox exporter runs as a second container of the same compose project (pinned by tag and digest, no published port, read-only, every capability dropped); the registry generator gains the `probe_targets` option (`hnx registry generate --only prometheus --probe-targets [--probe-exclude ROW]`), which lists every row published at the edge (probed by its edge name) or declaring an http health endpoint (probed by the name it answers by); a `probe` job reads it; and the `ProbeDown` rule (`probe_success == 0`, `for: 5m`, critical) goes through the existing state-diffed forwarder, so one message when a probe goes red and one when it clears.
