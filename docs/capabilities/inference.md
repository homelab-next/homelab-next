## What it does

Contract for `inference`: an OpenAI-compatible chat/embeddings endpoint.

Subject = `homelabnext.conform.adapters.openai_compat.OpenAICompat`-shaped client:

    models() -> list[str]
    chat(model, messages, *, max_tokens, temperature) -> ChatResult
    chat_stream(model, messages, *, max_tokens) -> Iterator[str]     feature `streaming`
    embed(model, texts) -> list[list[float]]                         feature `embeddings`

The embeddings checks call `embed_model` when the subject has one (an embedding role of the
target's own, set in its config), else the model the chat checks call.

A model *gateway* in front of the backends (LiteLLM; docs/llm-gateway.md) declares the
feature `gateway` and adds `GatewayClient`'s three methods, so the suite can prove what
the gateway is for: a bad key is a clean 401, a configured limit is a 429, and `/v1/models` is
exactly the declared role aliases.

A gateway whose keys are scoped by TLP ceiling (ADR-0033 decisions 10 and 11) declares the feature
`tlp-ceiling` and adds `TlpCeilingGateway.over_ceiling`: a key whose sending profile's TLP
ceiling is above the ceiling of a role whose prompts leave the lab is refused that role (a 401 or
403 on the chat, never a reply) while it is still served on a role it may call.  The per-request
half of the rule (a request's own label) is the caller's (`homelabnext.registry.model_tlp.admit`):
a gateway with no admission code of its own (LiteLLM) cannot read it.

A gateway that applies that rule itself to the label a request carries in the `X-HNX-TLP` header
(ADR-0038 decisions 5 and 7, the lab's own gateway) declares the feature `tlp-admit` and adds
`TlpAdmitGateway`'s two methods: clients that can send header fields
(`LabelledClient`), a role that leaves the lab, a role that stays in it, and a role whose
deployments fail and whose first fallback is refused at admission.  A refusal is a 403 whose error
names its reason (`unlabelled` or `above-ceiling`, `TLP_REASONS`).

A gateway that keeps a per-call log declares the feature `turn-records` as well: it offers a
`TurnSource`, `turns(start, end, tags)`, that yields the calls (*turns*) started in a
window and tagged with one of `tags`, each reduced to the neutral turn record
(`TURN_FIELDS`, checked by `turn_problems`).  How a product logs a call, and how it
receives the tag, is its adapter's business; orchestration telemetry
(`docs/orchestration-telemetry.md`) reads only this record.  The subject's
`TurnRecordsGateway.turn_records` names a window and tags known to hold turns, so the
suite can check them.

Errors are `InferenceError` with `.status` set for HTTP errors (and `.detail`, the
server's own message).  The target config says
which model to probe (`model`); by default the first model `models()` lists.

### `TlpAdmitGateway` (Protocol)

Defined in [`conformance.protocols.inference`](../../conformance/protocols/inference.py).

Feature `tlp-admit`: the gateway admits each request by the TLP label in its
`X-HNX-TLP` header (ADR-0038 decision 5): no field is `red` (reason `unlabelled` when
refused), one field is read with `tlp.read` (an empty or unknown value is `red`), more
than one field is `red`; a role that leaves the lab judges the request at the higher of its
label and the key's sending ceiling; a refusal of the requested role is a 403 at once, never a
fallback.

**Returns:** `tuple[LabelledClient, LabelledClient, str, str]`

`(sender, above, leaving, local)`: `leaving` is a role that leaves the lab, whose
ceiling is `clear` or `green`; `local` a role that stays in the lab; `sender` a
key whose sending ceiling is `clear` and that may call both; `above` a key whose

#### `TlpAdmitGateway.refused_fallback`

```python

```

**Returns:** `tuple[LabelledClient, str, str \| None] \| None`

`(client, role, served_by)`: every deployment of `role` fails with an error that
moves on, its first fallback is refused at admission (its own limit) and a later fallback
serves, so the call is served; `served_by` is the turn record `model` (feature

#### [`homelabnext.conform.adapters.openai_compat:OpenAICompat`](../../homelabnext/conform/adapters/openai_compat.py)

A small stdlib client for OpenAI-compatible servers (the `inference` contract).

- Target file: none in the repository (the contract module imports this client; it is driven by the fake's server in the suite)
- Factory: `OpenAICompat(base_url: str, *, auth: Callable[[], str | None] | None=None, timeout: float=10.0, features: Sequence[str]=('embeddings', 'streaming'), allow_plaintext: bool=False, max_bytes: int=16 * DEFAULT_MAX_BYTES)`

<details><summary>Full adapter notes</summary>

A small stdlib client for OpenAI-compatible servers (the `inference` contract).

`OpenAICompat(base_url)` implements `conformance.protocols.inference.InferenceClient`.
The base URL is always supplied by the caller (a fake's `.url`, or an endpoint the registry
resolver produced); there is no default.  An optional `auth` callable returns an
`Authorization` header value at request time so a secret is never held in the object.  With
`auth` set, plain `http` to a non-loopback host is refused unless `allow_plaintext=True`;
redirects are followed only within the same origin, and only for GET/HEAD; writes follow
none; no proxy is used (`HTTP_PROXY`/`HTTPS_PROXY` are ignored); replies are read up to
`max_bytes`.

`OpenAICompat.chat_fields` sends a chat with extra request header fields, each sent as a
field of its own even when a name repeats (`X-HNX-TLP` twice is two fields, which `urllib`
cannot send): that request goes over `http.client` directly and follows no redirect; it
connects to the gateway itself, so a header the test depends on is never rewritten or merged
by a proxy.

</details>

## Integrating a new product

1. **Implement the contract.** Write an object that satisfies `InferenceClient` (every operation above) and raises the contract's errors, never the product's own exceptions:

   ```python
   from conformance.protocols.inference import (
       InferenceClient,
       InferenceError,
       TurnSourceError,
   )
   ```

2. **Write a factory.** A target file names `package.module:factory`; the harness calls `factory(**config)` and runs the suite on what it returns. Take only keyword options; resolve the endpoint through the registry resolver (`HNX_ENDPOINT_INFERENCE` overrides it, as the lab-in-a-box smoke exports), never from a URL in the target, and read credentials from named environment variables at request time.

   ```python
   def make(**config) -> InferenceClient: ...
   ```

   The factory this repository ships: `homelabnext.conform.adapters.llm_gateway:make` is `make(*, roles: str, key: str='secret:llm-gateway/master-key', throttle_key: str | None=None, throttle_model: str | None=None, throttle_requests: int | None=None, over_ceiling_key: str | None=None, over_ceiling_model: str | None=None, over_ceiling_served: str | None=None, model: str | None=None, capability: str='llm-gateway', timeout: float=30.0, allow_plaintext: bool=False, embed_model: str | None=None, tlp_sender_key: str | None=None, tlp_model: str | None=None, tlp_local_model: str | None=None, failover_model: str | None=None, failover_served: str | None=None, telemetry_key: str | None=None, turn_model: str | None=None) -> GatewayTarget`.

3. **Describe the target** (YAML; `features` lists only what the product really offers; `waive:` takes SHOULD check ids with a reason, never a MUST):

   ```yaml
   name: my-target
   capabilities:
     inference:
       adapter: my_adapters.my_product:make
       config: {}
       features:
       - embeddings
       - gateway
       - streaming
       - tlp-admit
       - tlp-ceiling
       - turn-records
   ```

4. **Prove it:**

   ```
   hnx conform run inference --target path/to/my-target.yml -v
   hnx conform run inference --target path/to/my-target.yml --strict   # SHOULD checks too
   ```

   Every MUST check (22) has to pass. Then follow the [swap procedure](../swap.md) ([[swap]]) to replace the incumbent.
