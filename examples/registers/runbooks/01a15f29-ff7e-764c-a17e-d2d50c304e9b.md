## Purpose

Bring a new server under the private overlay and run its first deploy, dispatched by hand through the Actions Environment, without the workstation and without a secret in git (docs/private-overlay.md).

## Steps

1. Create the private repository from examples/private-overlay/, delete `fictional: true` from its marker and protect main with the checks job required.
   - verify: python3 hnx/tools/private_leak_check.py private . prints clean (private), and a pull request shows the checks job as required
2. Generate the operator's age identity and the ansible-vault password offline, store both in the password manager and on paper, and put the age public recipient in .sops.yaml.
   - verify: git ls-files lists no age identity or password file, and the private leak check reports no key-file finding
3. Initialise OpenBao in server mode with TLS, keep the unseal shares and the root token offline, write the lab's credentials under their secret names, then revoke the root token.
   - verify: bao status reports sealed false, and a read with the revoked root token is refused
4. Create the deploy AppRole (read-only on the paths the deploy needs) and the deploy age identity, and re-encrypt the sealed files for the new recipient.
   - verify: sops -d on each lab/sealed file succeeds with SOPS_AGE_KEY set to the deploy identity, and the AppRole token cannot read outside its paths
5. Give the deploy a path into the lab: the tag:ci-deploy stanza in the tailnet policy with a tag-scoped OAuth client, or a runner VM in the management zone registered to the private repository only.
   - verify: the tailnet policy lets tag:ci-deploy reach TCP 22 of the deploy zones and nothing else, or the runner shows online with the hnx-deploy label in the private repository only
6. Create the Environment production with deployment branch main only (add required reviewers only on a plan that has them; on Pro or Team the API call must omit reviewers), its secrets, and the variables HNX_REF, SOPS_VERSION, SOPS_SHA256 and HNX_DEPLOY_PATH.
   - verify: a workflow_dispatch from another branch is refused by the Environment, and the deploy's first step accepts the pins
7. Record each host's public SSH key in ansible/known_hosts after checking its fingerprint out of band.
   - verify: ssh-keygen -F <host> -f ansible/known_hosts finds every inventory host
8. Merge to main (checks.yml runs; deploy.yml does not), then dispatch the deploy with gh workflow run deploy.yml --ref main and watch the run end to end.
   - verify: the merge started no deploy run (gh run list --workflow deploy.yml), the dispatched run is green, its log shows no secret value (search it for each secret's first characters), and on the Tailscale path the tag:ci-deploy node is gone from the tailnet after the job
