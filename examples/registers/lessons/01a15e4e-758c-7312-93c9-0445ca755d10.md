## Symptom

Two merge requests each added `LL-040`; the second merge needed a hand renumber.

## Contributing factor

Authors read the file to find "the next free id" and appended an entry.

## Root cause

Id allocation was a read-then-write on shared state with no lock, so concurrent authors were guaranteed to collide eventually.

## Preventive control

Each lesson is its own file named for its uid (lessons/<uid>.md, a UUIDv7 created with the record), so two authors never edit the same file and never claim the same key: nothing is allocated, and the number a lesson is shown with is computed (docs/adr/0019-record-uids-computed-numbers.md). CI fails when a uid occurs twice, a file name disagrees with its uid, a record carries no uid, or a record present in the base has vanished.
