# generators

Contract and inventory for the registry generators. The code lives in
`homelabnext/generators/`; templates in `homelabnext/generators/templates/`
(stdlib `string.Template`, strict: a missing variable raises). Golden outputs
for the synthetic lab live in `tests/generators/golden/`.

Every generator is a pure function `Registry -> {relative path: text}`: no
clock, no randomness. Output carries `generated by hnx ... sha256:<digest>` so
drift is visible and stale files can be pruned safely.

Values are never escaped, so they are refused instead. `schemas/platform/service.json` (2.0)
gives every interpolated field a single-line pattern (owners and identifiers are slugs, paths
are URL path characters), and every pattern ends in `$(?!\n)` because Python's `re` lets `$`
match before a trailing newline. The renderers check again, for models built without
validation: `homelabnext/generators/safe.py` refuses control characters in any registry value
(`generate` checks the whole model first) and each format's metacharacters (`{ } #` for Caddy,
`| < >` for Markdown, and so on) with `UnsafeValueError`. The IdP blueprint is built as data and
written with a YAML dumper, never by text substitution.

See `manifest.yml` for the list (checked against the code by
`tests/generators/test_manifest.py`).

Refresh goldens after an intentional change:

    python -m homelabnext.registry generate examples/services.yml tests/generators/golden

then review the diff. SERVER: applying DNS zones to a live resolver, loading
Prometheus/Caddy/IdP output, and a Technitium HTTP adapter are deployment
steps, not part of this library.
