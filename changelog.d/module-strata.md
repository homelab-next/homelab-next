Module `modules/strata/` ([README](modules/strata/README.md)): a second `inference` provider beside `llamacpp`, on the Strata engine (MIT, C++/CUDA; release v0.2.22, commit `b28ca95e`), for one mixture-of-experts GGUF model on one NVIDIA GA100 card (the CMP 170HX, sm_80, 64 GiB). The same slot, shared conformance adapter and posture: one `compose_app` container started only by a unit whose `hnx-strata-precheck` refuses a power cap above 200 W, a guest that does not list exactly the expected GPU count, a stale CDI spec and any model file (every shard, an optional refusal-direction GGUF) that is not the pinned bytes; the weights read-only from the model store, no egress, no capability, named settings only (context, spec depth, KV mode, `kv_streaming`, `mmap_experts`, `pcie_frac`, `threads`, `vram_reserve_mib`; no raw flag). The image is built by the lab from the pinned tag and commit (`image/Dockerfile`: CUDA 13 base and runtime pinned by digest, sm_80 only, non-root; the recipe uses `--provenance=false --sbom=false`, `SOURCE_DATE_EPOCH` and `rewrite-timestamp`), deployed from an archive whose sha256 the role checks before `docker load`. Strata's `/metrics/prometheus` carries llama-server's `tokens_predicted_*` counters, so the metrics module's `prometheus_inference_metric_prefix: "llamacpp:"` makes `LlmDecodeCollapsed` read it unchanged. `tests/modules/test_inference_module.py` and `tests/roles/test_inference_server_role.py` now pin the first provider of the slot by id instead of asserting there is exactly one.
