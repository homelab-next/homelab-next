The lake writer no longer lets Iceberg snapshots pile up (LL-604: `soc.raw_archive` reached 5,070 snapshots in 19 h, its metadata passed the writer's 16 MiB catalog reply cap and the catalog ran out of memory). A run now commits all of a table's staged objects in one `write_batch` (up to `lake_writer_max_commit_rows`, default 100000) instead of one per object, with the same commit, checkpoint, delete order and replay guarantees. After a run whose commits all succeeded it expires snapshots beyond the newest `lake_writer_snapshot_keep` (500) or older than `lake_writer_snapshot_max_age_hours` (72) through the catalog's `remove-snapshots` (new `TrinoRestLake.expire_snapshots` and `RestCatalog.remove_snapshots`): metadata only, main's snapshot never, only tables whose refs are exactly `main`, and the run's JSON line reports `expired`, `snapshots`, `expire_skipped`, `expire_error`. The catalog reply cap is now `lake_writer_catalog_max_bytes` (default 64 MiB, `make_clients(catalog_max_bytes=)`), and a reply over it names how many snapshots it saw.
