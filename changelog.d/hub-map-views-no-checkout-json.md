The status hub's Topology, Dataflow and Schedule pages work without a checkout and are also served as JSON. Dataflow is drawn from the registry alone and Schedule from the registry's status collectors plus the jobs the hosts report (a new "Jobs the hosts report" group, every item of a `job-last-run` source with its hosts, newest run and worst state). `/topology.json`, `/dataflow.json` and `/schedule.json` return the view-model each page draws, withheld at `red` like the pages and written by `hnx status render --private-out` as `<panel>.json`. The `status_hub` role takes `status_hub_guests_src` and `status_hub_site_src` (the lab's guest directory and site model), delivers them beside the registry and passes `--guests` and `--guests-site`. The Topology (and the Dataflow's guest placement) now draws a guest set that breaks a rule `hnx guests validate` enforces, listing the problems under "Guest set problems" (the real lab has a known one, which made the page unbuildable); an unreadable or schema-invalid guest file still refuses.
