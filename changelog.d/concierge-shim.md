`modules/openwebui`: an optional concierge shim (`openwebui_concierge_enabled`), a standard-library OpenAI-compatible front between Open WebUI and the gateway, run as a sidecar of the same compose project from the pinned stock Python image with the code mounted read-only. It maps named model tiers (`fast`, `main`, `deep`) to gateway roles and lists a tier only while the gateway lists its role (so a tier appears when its role exists; a request for one that is not live is a 404, never a fallback), adds a site persona, trims history to a budget, and can add passages from the lab's context service at a TLP ceiling. Open WebUI holds only the shim's own token; the shim holds the gateway key, passes `X-HNX-TLP`/`X-HNX-Tag` through, and publishes no port. The core `open_webui` role gains `open_webui_connection_url`, `open_webui_connection_key_ref`, `open_webui_extra_services` and `open_webui_extra_secret_env` (all empty by default: no change). The shim answers malformed input with fixed 4xx/5xx messages, closes the connection on any refusal before the body is read, times out stalled clients, caps requests in flight (503), rewrites the model name in streamed chunks, reports a gateway 401/403 as 502 `upstream_auth_failed`, and only accepts a usage tag that extends the configured prefix. Note for sites with the shim off: the manifest now declares `secret:openwebui/shim-token` (read only when the shim is on), so `hnx secrets plan/seed` over the module's files will name it and need a rule for it (as it already does for the optional context token default).
