Standing failed units on the new lab, each from its own cause: `compose_app` export (`hnx-export-run`) listed databases with `psql -U <user>` and no `-d`, so an engine whose user is not also a database name (lakekeeper: user `lakekeeper`, database `catalog`; intelowl) failed every night with `postgres: exit 2`, now `-d postgres`; the export unit requires `docker.service` only when it has a postgres/mysql job (a unit-hosted state copy such as status-hub's failed its timer on a guest with no Docker); `clamav` masks Debian's second `clamav-freshclam-once.timer`, which collided with the freshclam daemon on its log lock every day; `media_automation` creates the `hnx-media` system account (the apps' uid/gid) because systemd refuses a numeric `User=` with no passwd entry (status 217/USER on all three helper timers); `source_census` puts `HNX_ENDPOINT_NOTIFY` in the unit's environment file so a newly flagged set can actually page instead of crashing with "cannot resolve capability 'notify'" (`source_census_notify_id`, default `notify`).
